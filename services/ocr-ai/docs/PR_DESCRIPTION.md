# OCR invoice evidence and fraud detection

This change adds source-grounded invoice and purchase-order extraction, document-injection signals, exact financial validation, duplicate checks, and explainable fraud-graph findings. It also adds generated multilingual reliability cases, the financing-document demo pack, repeatable evaluations, and the OCR handoff and runbook. OCR returns evidence and review signals; Policy owns financing decisions and Wallet owns execution.

The branch is based on current main (7c7056c). The latest release loop passes with `release_ready=true`: 184 OCR tests pass both locally and in a clean clone, 251 Policy tests pass with 3 skipped, and the integrated demo reports zero Policy guard violations. The injected case reaches review; a synthetic mismatch with fraud score 0.70 is rejected. The ordered OCR-only demo passes clean / injection / inflated / duplicate evidence expectations. Ruff, dependency checks, fixture generation, and protected HTTP extraction/result retrieval also pass in the fresh-clone run. Synthetic metrics remain limited to the generated corpus: 28/28 clean scalar fields, 16/16 injection catches with 0 changed grounded values, 0/20 hard-negative alerts, and planted fraud TP 8 / FP 0 / FN 0 / TN 4.

Remaining limits: the independent external invoice pack is still below the global header target; Chinese is experimental and Thai scan recovery has gaps; live hosted inference and a permissioned independent holdout have not been verified. The shared Policy request still lacks typed PO-comparison and full fraud-graph evidence. Issuer/bank/signature authenticity and settlement are unverified, and this PR does not establish wallet execution or a real chain transaction. No shared schema change is included.
