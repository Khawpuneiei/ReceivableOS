## Current behavior

`POST /ocr/extract` reads actual PDF/PNG/JPEG bytes (10 MiB), computes raw SHA-256 and extracts fields with locations. Unresolved required contract fields return 422. `/ocr/verify` independently compares invoice/PO, preserving match/mismatch/unknown and explicit line units; absent units cannot establish quantity/unit-price agreement. `/ocr/cases/verify` handles ten English supporting templates without claiming issuer authenticity or authoritative settlement.

Rules validate Decimal amounts, dates, Thai tax-ID checksum when jurisdiction is known, ISO currency, arithmetic and source evidence. Injection checks flag hidden, tiny, white-on-light, off-page, metadata, QR and Unicode instructions without allowing them to replace grounded values. Rules and bounded SQLite observations emit exact/semantic duplicates, arithmetic/PO discrepancies, bank changes, scoped shared accounts and narrowly defined clusters. Scores are uncalibrated rule aggregations, not probabilities. Raw accounts are transient and excluded from public graph/store outputs.

Explicit development mode permits public HMAC-key fallback with warnings and only the original PM text demo bytes. Default mode requires secrets. The legacy text sample's unknown jurisdiction/unit evidence routes to review; arbitrary text remains unsupported. Hosted vision needs `OCR_HOSTED_VISION_ENABLED=1` plus provider/model/key. Candidate readers never replace source-grounded fields. Per-key cache synchronization permits unrelated model requests to run concurrently while deduplicating identical misses.

The clean fixture target remains ≥90% (aim 98%). A prior four-scan experiment matched Paddle 24/28 fields and Qwen candidates 28/28; English tied at 14/14, Thai was 10/14 versus 14/14. Four scans do not establish general model superiority; latencies were uncontrolled. The published external synthetic development pack previously matched 180/232 header fields (77.59%), below target, and 322/396 line fields, with Arabic/bilingual and unlabelled-role gaps. No independent holdout or live hosted result is claimed. Companion documentation preserves these historical findings; reproduce them separately before making new performance claims.

## Integration boundary

Policy's own guards reject fraud ≥0.30 and review injection/low confidence. The shared request accepts the invoice projection; adoption of local PO/case/graph evidence remains a separate PM contract decision. Wallet/registry runs here use mock infrastructure; checks do not prove chain enforcement or settlement. Remaining production work includes independent licensed holdouts, adjudicated fraud labels, authenticated issuers/accounts, tenant isolation, key lifecycle and reviewed history migration.
